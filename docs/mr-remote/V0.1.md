# MR Remote — V0.1.0

Base: RustDesk 1.5.3, commit `95cca3f661f635b3cc85c04935fe8d96d8f432ef`.

## Escopo
- Windows x64, Flutter e Rust originais.
- Preservar autenticação, consentimento e criptografia.
- Manter licença AGPL-3.0 e avisos originais.
- Não publicar binários de teste como produção.

## Validação funcional — 24/11/2026
- [x] Fork, branches e workflow Windows x64 sem credenciais de assinatura upstream.
- [x] Compilação Windows x64 e abertura do aplicativo.
- [x] HBBS/HBBR OSS 1.1.16 na AWS EC2 Ubuntu 24.04 LTS.
- [x] Comunicação TCP e UDP, acesso entre redes distintas e Relay forçado.
- [x] Mouse, teclado, arquivos, clipboard e encerramento da sessão.
- [x] Senha incorreta rejeitada, consentimento e rejeição de acesso.
- [x] Persistência de chaves, backup criptografado externo e integridade/descriptografia verificadas pelo responsável.

Evidências: Issues #2, #3 e #4. Build Windows bem-sucedido em 51m18s: https://github.com/raffaelpereirasilva94-rgb/rustdesk/actions/runs/45417204474 . CI convencional bem-sucedido; Full Flutter CI upstream apresentou startup_failure. Artefato de teste sem assinatura, não MSI nem executável autônomo. Validação de usuário não equivale a auditoria independente.

## Limites e revisão antes de produção
- Revisar PRs e integrar as branches antes de iniciar V0.2; nenhuma publicação comercial nesta fase.
- Workflow manual disponível na branch padrão após integração; gatilho push atual limitado à branch de validação. Rever gatilhos para V0.2.
- Downloads upstream do engine Flutter e drivers não estão todos fixados por digest independente; revisar cadeia de dependências e assinatura digital antes de distribuir.
- AWS Free Plan temporário; acompanhar créditos, IP público sujeito a alteração e tráfego Relay. Planejar migração, backup completo, monitoramento e revisão de segurança.
- Manter `master` preservada; `main` base estável; `develop` integração. Não publicar senhas, chaves privadas ou dados de clientes.
